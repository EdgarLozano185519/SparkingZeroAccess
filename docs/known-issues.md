# Known Issues

## Open (2026-09-13, branch feature/pipe-speech-game-thread)
- World Tournament → offline mode crash: not retested since the GC-safe registry (below). Since 2026-09-13 afternoon every game-thread crash leaves evidence: the speech plugin's crash catcher logs the exception with a stack walk in `Win64\plugins\SparkingZeroSpeech.log` and writes `Win64\plugins\AE_crash_<time>.dmp` (read with `experiments\mdump.py`), and `helpers\Launch-Game.ps1` / `Drive-Game.ps1` print the process exit code. Exit code 3 = Unreal's own `RequestExit(true)` after a fatal error (the "silent exit"): no dump from UE4SS, no Windows event, but the plugin sees the exception first
- Once, the game died 3 s after start with exit code 3, no exception seen by the plugin and no "Process exiting" line (so a TerminateProcess, most likely UE's fatal-error exit), on the stable UE4SS 3.0.1 build (1 of 6 launches, 2026-09-13). The experimental UE4SS build died the same way every time; the plugin now also captures UE's fatal-error text (exception code 1, `GErrorHist`) and the last OutputDebugString lines, so the next such death should name its cause
- Walks (`FindAllOf`) while the game streams assets can crash: objects are registered in the object array before their fields are initialised, and UE4SS's IsA/IsChildOf reads them (crash 2026-09-13 09:18, garbage class pointer, during the title load, no GC involved). objects.lua keeps walks rare (no reactive walks during transition cooldowns); a residual risk stays. The experimental UE4SS build's hash-table lookups would remove it if that build can be made to run
- The installer ships the plugin files (added 2026-09-13) but has not been built or tested since

## Fixed (2026-09-13 afternoon)
- Title screen regression ("Press confirm to start" and the title buttons not read): widget blueprint classes (`WBP_*`) are now served from a `UserWidget` walk that runs every 3 s in menus and on request when nothing has keyboard focus, so a new screen is in the cache within about a second. Verified with Drive-Game (title buttons, main menu, roster, CPU level read)
- Cached references crashed the game after a garbage collection (crash 2026-09-13 09:03, AV reading `obj+0xC` = InternalIndex on the game thread): UE4SS 3.0.1's `IsValid()` reads the object's own memory, so on a freed and unmapped page it crashes instead of returning false. objects.lua now detects every GC with a sentinel object (see "SAFETY" in objects.lua) and flushes every cached reference (registry and modules, via `Objects.OnFlush`) before anything touches it

## Mod Issues
- UE4SS GUI debug window disabled (GuiConsoleVisible=0) for accessibility
- Team slot character names use texture ID lookup — new DLC characters need to be added to chara_names.lua
- FindFirstOf may return CDO (class default object) instead of live instance — always check for "Transient" in path or use FindAllOf with path filtering
- UE4SS hot reload (Ctrl+R, EnableHotReloadSystem=1) freezes the game and the mod. Keep it disabled and restart the game after deploying
- Crash on screen changes (World Tournament, title → main menu) in versions up to 1.0.1: the mod polled widgets from LoopAsync, off the game thread, while the game freed them (dump: read of 0x40 = UStruct::SuperStruct through a null class pointer inside an object walk). pcall cannot catch it. Since 2026-09-12 all polling runs on the game thread (game_thread.lua) and lookups come from objects.lua's cache, which is flushed at every garbage collection since 2026-09-13 (see Open for what remains)
- UE4SS 3.0.1 `obj:IsValid()` is NOT safe on freed objects: it reads the object's InternalIndex from the object itself, then checks the Unreachable flag and UE4SS's map of live objects (kept current by a delete listener). It only returns false safely while the freed memory is still mapped. Never keep a UObject reference across ticks outside objects.lua's flush protection
- UE4SS 3.0.1 `StaticFindObject(path)` is a linear search over all objects (15 ms here), not a hash lookup, and it does not find the package `/Engine/Transient` by name (reach it through `GameInstance:GetOuter():GetOuter()`). `StaticConstructObject(class, outer, FName(name))` works on the game thread
- The game runs a garbage collection every frame during screen transitions (bursts of 2–5 consecutive "garbage collection detected" lines), plus the usual periodic ones. Each detection flushes the cache and the next ticks walk the queried classes again (one walk per tick, 30–60 ms each)
- The LoadMap hooks (RegisterLoadMapPreHook/PostHook) never fire in this game after startup: the battle map and menu transitions use seamless travel or streaming. `[AE] Map loaded` appears once per launch. main.lua tracks the PlayerController instead: every world gets a new one, so the old one dying is the world-change signal
- RegisterHook on `/Script/Engine.PlayerController:ClientRestart` from this mod killed the game at startup (2 of 2 runs, 2026-09-13), although CheatManagerEnablerMod hooks the same function. Probably Lua running on the hook thread while the mod's LoopAsync timer runs Lua too. Don't add RegisterHook callbacks to this mod while the timer path is in use
- Walking the base classes with FindAllOf("Widget") or FindAllOf("Actor") killed the game (2026-09-13). Only walk the class names the mod already used (UserWidget, TextBlock, RichTextBlock, Image, WBP_*, Pawn, PlayerController, GameInstance, ...). No walk during the first 5 s after mod start either (game still loading)
- UE4SS 3.0.1 Lua: UFunctions with out params are broken (an out param followed by other params leaves its table on the Lua stack; TArray out params are never written back), so engine enumerators like WidgetBlueprintLibrary::GetAllWidgetsOfClass cannot be used. Errors from such calls arrive as a Lua function value, not a message
- UE4SS 3.0.1 Lua: NotifyOnNewObject callbacks run Lua on the thread that constructs the object (loading threads included) with no lock. Not usable
- UE4SS experimental builds (tested UE4SS_v3.0.1-1133-gb4cefa18) kill this game about 3 s after the mods start, even with SparkingZeroAccess disabled in mods.txt, with no dump. Stay on 3.0.1 (helpers\Switch-UE4SS.ps1 -Build stable restores it). The same death happened once on 3.0.1 (exit code 3, see Open); a retest of the experimental build with the plugin's crash catcher would show whether it is the same cause
- On 3.0.1 every FindAllOf/FindFirstOf walks all objects: 28–50 ms each on the game thread (136–150 ms while the game loads). objects.lua walks at most one class per tick, none while a battle is busy
- bUseUObjectArrayCache = true does not speed up lookups on 3.0.1 and makes loading very slow. Keep it false
- Episode Battle story map: the episode nodes are 3D level actors (Map800_Chart_* level instance), not widgets. Cleared/locked status per node is not read yet; chart_actors.txt (F6) is the starting point
- Episode Battle story map: on path nodes Text_EventTitle is collapsed but keeps the previous episode's text. Detect "back on an episode" by title visibility, not text changes
- Episode Battle story map: consecutive path nodes only differ in the title panel's OtherCharaIcon portraits. What the portraits represent is unconfirmed
- Episode Battle popups (Details/Recap, Episode Map) stay alive and IsVisible() after closing, with their root at opacity 0. Use SSMenuWidget.bIsActive + opacity to detect "open"
- Episode Map "main story" / "what if" route labels are a guess: row 00 = main story, other rows = what if
